## 当前环境与代码审计

CN 已安装 **DsN 6.4.1 / PF2e 8.5.1**。当前 [DsN 官方 manifest](https://gitlab.com/riccisi/foundryvtt-dice-so-nice/-/raw/6.4.1/module/module.json) 要求 Foundry v14；[PF2e 8.5.1 manifest](https://raw.githubusercontent.com/foundryvtt/pf2e/pf2e-8.5.1/system.pf2e.json) 最低版本为 14.361。安装代码有 25 个 JS 文件、5,090 行，另有 307 行 CSS。

主要结构：原生窗口 render → 提取骰子槽 → spawn → 聊天钩子扫描物理结果 → 自动提交 → close 将结果放入每玩家队列 → 包装 PF2e Roll.evaluate → 注入单个骰子结果。

需要重做的具体点：

1. DsN 6.4.1 将顶层 `spawnPersistentDie`、`removePersistentDie`、`_emitPersistentEvent` 及旧持久化状态迁入 `game.dice3d.persistent`。这些是本模块的实际失效点；DsN 原生 `_roll` 管线也已重构，但 0.4.10 的结果注入实际包装 `Die.roll()`，不是包装该 DsN 管线。
2. 旧 `PendingQueue` 只按玩家索引，无法证明下一次 evaluate 就属于刚完成的检定；重做必须绑定确切会话和 Roll。
3. 旧收值流程扫描全体持久骰子，可能读到历史 `forcedResult`；新流程需要会话、骰子 ID、投掷代次、落定完成四项匹配。
4. DsN 的持久投掷会广播真实结果，即便 spawn 时 `synchronize=false`。隐藏数值或问号皮肤不能保护网络数据。初版私密检定应保留 PF2e 原生保密流程。
5. DsN 已有原生持久骰子和抓取/旋转/投掷引擎；无需新增物理引擎或常驻第二套 WebGL 渲染器。
6. Foundry v14 的 dice fulfillment 配置是全局/用户骰型配置，不能直接实现“只替换本次物理检定、原生按钮仍用 RNG”。不把它当成无需包装的替代方案。

本轮完成恢复、文件校验和源码研究；尚未验证重设计的浏览器交互，也未适配或部署新的运行代码。
