# Persistent Dice：八角骰盘重设计

日期：2026-09-30。状态：用户以“继续”认可设计，进入实施计划阶段，尚未开始实现。

## 目标与基线

将现有 `pf2e-dsn-persistent-bridge` 改为原生检定窗口 + 画布右下角三维八角骰盘。删除检定窗口底部的槽位面板、教程式文案和快捷设置条。玩家打开原生检定或伤害窗口后，可以在骰盘中长按抓起本次全部骰子，拖出、旋转、松手投掷。PF2e 继续负责修饰符、成功等级、伤害计算、聊天消息和资源变化。

当前请求已经确定：八角形骰子托盘、平时可空盘、按检定骰数生成、长按整把抓取、小骰子抓出后放大并进入旋转状态、松手或甩出投掷、原生检定可用、精简代码与文案。

按旧项目行为及本次继续的设计采用：**公开投掷使用物理落定点数作为 PF2e 输入**。如果用户后续改为原生随机数决定结果，应切换到 DsN 的原生交互展示路径，并删除物理输入桥接。该选择影响实现，不应在代码中暗自混用。

DsN 的具体机制是在释放时生成随机数，再让物理动画落成这些点数；“落定点数作为输入”指 PF2e 使用本次实际显示的同一结果。鼠标动作决定动画方向和速度，不改变随机分布；PF2e 不提前生成另一个结果。

适配目标为 [DsN 6.4.1](https://gitlab.com/riccisi/foundryvtt-dice-so-nice/-/raw/6.4.1/module/module.json)、[PF2e 8.5.1](https://github.com/foundryvtt/pf2e/releases/tag/pf2e-8.5.1) 和 Foundry v14。重启基线包含已恢复的服务器 0.4.10 修复，而不是仅使用公开 0.4.9。保留模块 ID 以接续安装与设置。恢复证据见 [项目恢复记录](../../recovery-20260930.md)。

## 方案选择

| 方案 | 取舍 |
| --- | --- |
| **复用 DsN 场景与物理引擎，重写托盘和会话桥接（建议）** | 可做真正三维托盘，保持原有物理结果输入；少量内部接口集中在版本适配层 |
| PF2e 随机数 + DsN 原生交互展示 | 最容易维护、可减去结果注入；抓取动作不决定点数，与旧项目目的有变化 |
| 单独渲染器、物理引擎和八角碰撞边界 | 可以完全控制盘内模拟，但重复 DsN 功能、维护与性能成本高，不符合本次精简目标 |

建议采用第一种。托盘负责收纳和发起投掷，骰子被抓出后在 DsN 画布上正常投掷。**本次不新增盘内八角物理碰撞模拟**；托盘本身仍是真实的三维八角几何体，不用 CSS 平面图代替。

## 玩家交互

### 空闲

- 骰盘固定在画布右下角，避让展开的聊天栏、宏栏及已有控制区域。
- 初始尺寸约 210–230 CSS 像素宽；浅俯视视角、低盘沿、八角底面，材质保持克制，适配亮/暗主题。
- 平时为空盘，不放标题、常驻说明、槽位数字、锁按钮或画质按钮。
- 每个客户端有自己的骰盘。盘本身不通过 socket 同步。
- 空盘稳定后只在尺寸、主题、场景或内容变化时请求重绘。保持盘可见不能间接唤醒 DsN 持续渲染、worker 更新或模块自己的 requestAnimationFrame 循环。

### 打开原生窗口

- 原生 CheckModifiersDialog / DamageModifierDialog 的布局与提交按钮保持原有交互。
- 骰盘生成本次所需的三维小骰子，骰型、数量和伤害类型来自窗口的有效公式。
- 小骰子使用玩家现有 DsN 外观。相同面数、不同伤害类型保持各自外观和结果对应关系。允许抓取前必须确认当前 PF2e 路径能绑定确切的 Roll；不支持的路径保留原生检定，不先展示物理结果再偷偷更换为 RNG。
- 切换 fortune/misfortune、伤害骰开关、暴击计算或有效公式时，取消旧投掷会话并重建所需预览。数量未变但类型改变也必须更新。
- 多窗口同时存在时，骰盘跟随最近聚焦的有效检定窗口；每个会话独立。投掷期间不切换到另一个会话。

### 长按、抓起、投掷

1. 在盘内按住约 300ms，抓取当前检定全部骰子。短按不触发投掷。
2. 抓取确认后给予轻微抬起与盘沿反馈，不弹出提示框。
3. 拖离盘面时，小骰子转换为 DsN 正常尺寸的持久骰子，约 150ms 平滑放大。实例归本次会话和发起者所有。
4. 自动进入 DsN 的抓持旋转状态，无需手动摇到旧震动阈值。
5. 松手即投掷。甩出时沿手势方向和速度投掷；静止松手采用稳定、有限的默认初速度。
6. Esc、指针取消、窗口关闭或页面失焦会取消抓取，清除本次临时实例并恢复合法预览，不自动提交。
7. 原生 Roll 按钮随时可用：未投掷时走原生随机数；已有部分结果时，仅消费当前会话已确认落定的骰项，其余调用原生 RNG。抓持中或飞行中点击 Roll 会取消未完成部分；之后到达的旧完成回调不能收值或再提交。不会消费其他窗口、装饰骰或历史投掷。本次移除旧的 requireAllSlots 分支，只保留这一种部分提交规则。

键盘聚焦骰盘后，按住空格使用相同抓取流程，松开投掷；Esc 取消。可见 UI 不增加一排按键说明，保留简短 tooltip 与无障碍名称。

### 落定与提交

- 等 DsN 明确完成本次物理投掷后收值，不用固定几秒计时推测完成。
- 骰面与 PF2e 消息必须一致。全部有效骰子完成后默认自动提交原生窗口一次。
- 原生按钮提交、自动提交和窗口关闭竞争时，只允许一个提交分支生效。
- 只产生一条 PF2e 检定/伤害消息；抑制本次任务骰的独立 DsN 聊天消息和重复动画。
- 投掷完成后清理本次骰子，托盘恢复空盘；不遗留后台扫描队列。
- 原生重投流程保留；无标准检定窗口的英雄点/fortune 重投走原生流程，不沿用“先扔一颗、再点重投”及旧剩余骰队列。

## 私密检定与多人行为

DsN 6.4.1 的持久投掷原生广播包含真实点数。`synchronize=false` 和问号皮肤不足以保护暗骰。初版对 blind / GM private / self 等非公开检定保留 PF2e 原生结果路径，不创建会广播真实结果的物理任务骰。

骰盘保留安静的不可操作状态，使用原生样式的眼睛图标与简短“私密检定”tooltip；原生检定按钮正常工作。检定模式在抓取前或投掷中改变为私密时，使公开物理会话失效、丢弃已收物理值，并为新的私密检定使用原生随机数。已经公开广播的数据不能撤回，因此旧公开投掷的异步结果绝不能成为私密检定的结果。将来若要私密物理投掷，必须单独设计按收件人过滤的结果传输与本地模拟，不能靠隐藏 UI。

公开任务骰默认只有发起者可操作。公开运动尽量使用 DsN 原生同步；不再维护一套常驻 mirror 骰与周期清理器。仅显示自己持久骰子的客户端，在允许公开动画时用一次性 DsN 原生动画展示他人本次投掷，不生成他人的常驻预览或接收端 mirror。明确关闭所有骰子显示的客户端保持不显示。只清理本模块、当前会话拥有的实例。

## 技术结构

计划保留六个明确边界，实际文件组织可按实现需要调整：

| 单元 | 责任 |
| --- | --- |
| PF2e dialog adapter | 观察原生窗口、提取有效骰项与消息模式、触发原生提交 |
| Roll session | 绑定 app / user / 骰项 / 骰子 ID / 投掷代次 / 提交状态；管理取消与一次性消费 |
| Tray view | 三维八角几何、静态小骰子预览、视口避让、可见性与尺寸更新 |
| Gesture controller | 长按、指针捕获、提升、旋转、释放、取消；不处理检定算式 |
| DsN adapter | 外观、无物理预览、原生 spawn/grab/throw/remove、完成事件、版本检查 |
| PF2e result bridge | 将确切会话绑定到本次 CheckRoll/DamageRoll，只注入其骰项；默认 Roll 原样运行 |

### 三维与物理

DsN 当前 Three.js 模块为 `modules/dice-so-nice/libs/three.module.min.js`。托盘可作为模块拥有的 Group 放入 `box.scene`。预览使用 `box.throwEngine.createDiceMesh(...)` 生成外观一致的无物理 mesh；预览不得加入 `persistentDiceList`。

抓出后使用 `game.dice3d.persistent.spawn(...)` 生成正常大小的原生骰子，再进入 DsN 抓持/预投/投掷。内部抓持与 scene/factory 接口集中在一个适配层，启动时验证能力，不能散落多个 prototype patch。

原生拾取不会检测无物理预览，骰盘使用独立命中区域。须处理 DsN 的 canvas 自动隐藏：空盘仍可见，托盘存在时的可见性覆盖仅限适配层，关闭模块后恢复原行为。不得为保持空盘而持续执行动画循环。

DsN resize/重建 box 后，重新绑定当前场景并重建托盘。只 dispose 模块自建几何和材质；不能释放 DsN 缓存或其他骰子共用的几何、材质、纹理。

### 结果绑定

删除按玩家“取下一次 Roll”的队列。公开物理会话必须用明确标识绑定到对应的原生 Roll 创建/提交路径；不能依靠“刚关闭的窗口”“下一个同公式 Roll”或全局临时变量猜测归属。绑定能力必须在允许抓取前确认；不支持的路径从一开始保留原生检定。若常规检定或伤害路径始终无法精确绑定，则本方案没有达到完成条件，不能以投完后更换 RNG 作为完成。

如必须包装 evaluate，只包装 PF2e CheckRoll/DamageRoll，并通过本次 Roll 的私有会话标识查找数据；不更改全局随机生成器，不修改 core.diceConfiguration。单骰注入继承 0.4.10 的单次 `Die.roll()` 语义，随机补骰仍调用原函数。所有修改在 finally 中恢复。

实施计划的源码核对确认：本轮可证明的身份载体为普通检定、原生武器/近战武器伤害及原生法术伤害。元素冲击和内联伤害在当前 PF2e 中没有可用的窗口到 Roll 身份通道，这些入口从抓取前保持原生检定；不能以相同公式或“下一次 Roll”宣称支持。其余路径通过 domains/base/context 对象引用绑定。

支持嵌套伤害项、fortune/misfortune、暴击额外骰、d100 组合、部分提交、重投/爆骰的随机补项和不同伤害类型相同面数的正确分配。描述符应包含骰项路径与类型，不能只用 faces 做一个全局 FIFO。

### 错误与清理

生成实例的异步操作须带会话代次；关闭/重建后的旧 await 结果立即移除。取消先解除抓持约束，再移除物理骰子。异常或依赖接口不符时释放资源，原生检定继续可用；提示简短，诊断留在按需日志/API 中。

## 删减范围

- 删除 `templates/slot-tray.hbs`、窗口内旧槽位面板和相关 CSS。
- 删除自动欢迎聊天消息、教程式提示及冗长设置说明。
- 删除画质轮换、震动灵敏度对话框、右键投掷补丁、自动全选设置；新抓取手势替代这些操作。
- 删除旧跨客户端 mirror、定时全量扫骰、旧 per-user PendingQueue 和先扔后点的重投队列。
- 重写 `spawn-helper.js` / `socket.js` 的必要功能，优先使用当前 DsN 原生能力。
- 保留并更新骰项提取、伤害类型外观、一次提交和重复动画抑制；只有源码及测试证明已由上游覆盖，才删兼容代码。
- RNG Guardian 不再自动改写其他模块的全局忽略列表。对物理结果和原生 RNG 的冲突先明确行为，只为实际冲突提供简短设置提示。
- 对外名称与文案简化为 Persistent Dice / 骰盘。初步设置保留启用、骰盘尺寸、自动提交和诊断日志；旧设置做一次性迁移，不继续暴露历史快捷控件。
- 旧“禁止玩家生成装饰骰”是对 DsN 工具盒的额外限制，本次随相关补丁删除；装饰骰权限由原生 DsN/Foundry 设置管理。装饰骰仍不会成为检定输入。这里是简化后的明确行为，不把旧限制值静默迁移成另一种限制。

## 验证与完成条件

实现后在隔离测试世界验证，不用生产世界充当交互实验。测试覆盖：

| 场景 | 必须成立 |
| --- | --- |
| d20 / fortune / misfortune | 预览数量正确，物理骰面与聊天结果一致 |
| 混合伤害 / 暴击 / RE 公式 | 数量、骰型、类型和对应伤害项正确 |
| d100 / 部分提交 / 补骰 | 不双加结果、不出现 0/NaN，不消费历史值 |
| 原生按钮 / 跳过窗口 / 宏 / 原生重投 | 原有 PF2e 行为可用，无额外 resolver 提示 |
| 双窗口 / 同时 Roll / 快速开关 | 会话不串值，旧 async 和定时器不提交新窗口 |
| 松手 / 甩出 / Esc / 失焦 | 每次仅投掷或取消一次，原生拖图操作可用 |
| 公开多人 / 暗骰 / 私密 / 自骰 | 消息权限正确，非公开点数不进入公开 DsN socket |
| resize / 场景切换 / DsN box 重建 | 托盘仍在正确位置，不遗留 mesh、材质或监听 |
| 空盘与落定后的性能 | 空盘只按需重绘，不唤醒原生持续渲染或 worker；无常驻 RAF、全量轮询，资源可回收 |
| 中英文 / 亮暗主题 / 键盘 | 无旧面板、冗长文案及多余消息，基本操作可达 |

关键状态、公式和结果绑定需有有意义的自动测试；三维手势、可见性和多客户端点数一致性需在真实浏览器验证。编译/语法检查不能代替这些完成条件。
